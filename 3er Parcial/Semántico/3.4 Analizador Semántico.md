## 1. Teoría

Ahora que el árbol sintáctico está construido y la estructura gramatical está validada, el compilador entra a una fase crítica enfocada en el contexto. El análisis semántico es el proceso que verifica que el código fuente sea semánticamente consistente con la definición del lenguaje. Mientras el análisis sintáctico se asegura de que una oración esté bien formada, el análisis semántico verifica que dicha oración tenga un significado lógico y válido dentro del programa. Este análisis previene errores lógicos en tiempo de ejecución validando reglas contextuales que las gramáticas libres de contexto no pueden detectar de forma aislada.

## 2. Herramientas y Técnicas

Esta fase requiere componentes específicos para rastrear y comprobar el estado del programa:

- **Tabla de Símbolos:** Es la estructura de datos principal utilizada en esta etapa. Actúa como un diccionario en memoria que rastrea todas las vinculaciones de los identificadores, almacenando información crítica como el nombre de las variables, su tipo de dato y su ámbito o alcance lógico (_scope_). El analizador sintáctico a menudo accede a esta tabla de forma anticipada para asistir en las funciones del analizador semántico.

- **Comprobación de Tipos (_Type Checking_):** Es la técnica central, propia del análisis semántico, donde el compilador valida los atributos de los datos para definir qué operaciones son permitidas entre ellos.

- **Coerción (Conversión implícita):** Si el lenguaje es débilmente tipado, el analizador utiliza reglas semánticas para convertir automáticamente un tipo de dato en otro esperado para evitar que la operación colapse (por ejemplo, sumar un entero con un flotante).

- **Gramáticas de Atributos:** Técnica para incrustar la información semántica (el "tipo" y el "valor") directamente en los nodos del Árbol Sintáctico Abstracto (AST) para su uso en las etapas posteriores.
## 3. Manejo de Errores

El manejo de errores en esta etapa se centra en identificar inconsistencias lógicas en programas que, a primera vista, son sintácticamente perfectos. Los problemas más comunes interceptados aquí incluyen:

- **Errores semánticos:** Consisten fundamentalmente en aplicar un operador a un operando incompatible. Un ejemplo clásico es intentar asignar una cadena de texto a una variable declarada explícitamente como número entero.

- El uso de identificadores (variables o funciones) que no han sido declarados previamente en el entorno de ejecución actual.

- Inconsistencias en las firmas de las funciones, como invocar un método enviando una cantidad incorrecta de argumentos respecto a la definición original de la función.
## 4. ¿Cómo se construye?

A nivel de ingeniería de software, la construcción de un analizador semántico se implementa generalmente como un algoritmo de descenso recursivo que recorre y visita exhaustivamente las ramas del Árbol Sintáctico Abstracto (AST).

Durante este recorrido estructural, el compilador consulta constantemente la Tabla de Símbolos para validar el ámbito y las declaraciones previas. Si al cruzar cada nodo se cumplen todas las reglas lógicas y de tipado, el analizador "decora" o anota el árbol sintáctico con la información validada, dejándolo completamente preparado, limpio y seguro para iniciar la fase de síntesis o generación de código intermedio.
